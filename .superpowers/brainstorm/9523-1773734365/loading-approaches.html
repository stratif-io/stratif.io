Loading UX — 3 Approaches

Which strategy fits best? You can select multiple.

A

Deferred skeleton + fade-in

Don't show the skeleton at all until 200ms has passed. Fast loads (under 200ms) show nothing — content just appears. Slow loads show the skeleton briefly, then fade content in smoothly when ready.

✓ Eliminates flash for fast loads ✓ Smooth transition always ◦ Small code change per component
B

Stale-while-revalidate

TanStack Query's staleTime: show cached data immediately on page revisit — no skeleton at all. Fresh loads still show a skeleton, but navigating back feels instant. Works best when users revisit pages often.

✓ Instant revisits ✓ No skeleton on back-navigation ◦ Data can be slightly stale
C

Skip skeletons, animate in content

Remove skeletons entirely. Show the page structure immediately (empty metric cards, empty chart area) and animate numbers/content in when data arrives — count-up for metrics, fade-slide for charts. Dashboard already has count-up on MetricCard.

✓ No flash ever ✓ Feels like the app is alive ◦ Layout must be stable without data
